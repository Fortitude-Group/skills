# Phase 1 — MINE

Purpose: sweep a territory and surface candidates with evidence attached.
A mining pass ends with a ranked list where every entry already has a
verdict-grade one-liner — not a brainstorm of maybes.

## The four mining methods

Pick the method(s) for the pass explicitly; tell the user which you're
running.

### 1. Deadline-driven demand (highest hit rate)
Regulations, end-of-life dates, platform sunsets, and pricing cliffs that
FORCE spending by a date — the deadline does the selling, which suits
operators with weak marketing. Hunt in: new legislation with phased
commencement, regulator enforcement roadmaps, tax/filing digitisation
programmes, product EOLs, mandatory scheme registrations.
Rules specific to this method:
- Verify the date against the regulator/government's own text. Note
  whether it has already been delayed once (delay history predicts
  further delay — score deadline pressure down and add an instant-kill
  trigger for further slippage).
- Ask *who the forced spend actually flows to*. Many real deadlines pay
  telecoms/hardware/consultants, not software — if the money doesn't
  naturally buy software, kill early.
- Check for a revenue cliff after the date. One-off migration deadlines
  make bad subscriptions.
- Check whether the *first* panic wave has already happened and been
  absorbed by incumbents.

### 2. Complaint mining
Pull 1–3★ reviews of the top ~5 incumbents in a vertical; extract
recurring complaints; mine forums/Reddit/Hansard/issue trackers for
"why is there no tool that…"; scan Upwork/Fiverr for recurring gig types
(recurring paid gigs = pre-SaaS demand). Classification happens in
Phase 2; at mining stage you're looking for *any* recurring complaint
signal worth a drill.

### 3. Boring vertical SaaS
Niche industries with money and 2005-era software. WARNING, learned the
hard way: this territory has been heavily colonised by AI-assisted
micro-SaaS founders since ~2023. Before proposing any boring vertical,
run the three-way competitor search (Iron Rule 4) *during the mining
pass*, not later — most "obviously underserved" niches now have 3–6
recent entrants. Prefer verticals protected by a moat the operator can
hold: regulatory complexity, gnarly technical formats, or a
recognition/listing gate that filters competitors without blocking
independents.

### 4. Platform shocks & incumbent decay
Pricing revolts, licence changes, acquisitions-followed-by-neglect,
API shutdowns. Test: is the resulting pain *recurring* (subscription-
shaped) or a one-time migration (services-shaped)? Is the gap structural
or will the platform close it? If the fix depends on scraping or
un-sanctioned automation against the platform, treat it as a treadmill
business and score competition/moat accordingly.

**Portfolio-acquirer sweep (a variant).** Serial acquirers that buy
software and cut costs (Bending Spoons is the archetype) follow a
repeatable sequence: deal, mass layoffs within weeks, price and free-tier
changes 3–12 months later, usage-based repricing at the second renewal.
Refugees move in the 12–24 months after. To mine one:
- Map the whole portfolio from primary sources (prospectus, filings) with
  acquisition dates; it will keep growing, so date the map.
- Set the complaint window per product: acquisition date to today.
- Place each product on the timeline. Early (pre-repricing) products are
  where windows are opening; the attack should be ready for the
  repricing email. Late products usually have closed windows: winners
  already absorbed the exodus (Obsidian after Evernote).
- Frame against the right incumbent. The acquired product is often not
  the real competitor for the segment you'd serve (e.g. a cycling route
  app versus the motorcycle specialists). Name the actual incumbents.
- Treat owner claims and competitors' "X is dying" posts as class C
  evidence; prefer filings and reputable press.
- Run Phase 3b early: most portfolio products fail the power test for a
  new entrant even when they're easy to rebuild.

## Search discipline for a pass

- Budget searches per pass (6–10 typical) and spend them on the
  *uncertain, high-value* facts, not on things already known.
- For every candidate that survives to the ranked list, at least one
  primary-source verification must already be done.
- Record verification dates. Facts decay.
- When a search kills a candidate mid-pass, keep it in the write-up as a
  named kill with cause of death — kills are deliverables.

## Pass output format

Ranked candidates, best first. For each: what it is (one line), the
evidence class (verbatim complaint / verified deadline / paid workaround),
the honest adversarial note you already see coming, a provisional
power-path score (0–3, with the likely primary power), a rough gut
P(revenue) % with one line of reasoning (formalised into a full EV block
in Phase 4), and a provisional verdict: promote to DRILL / park (with
what would revive it) / kill (with cause). Close the pass with what it taught about where to mine next —
including "this territory is picked over" when true.
