# Phase 5 — HANDOFF (Spec-Ready Briefs)

Purpose: turn each EXTEND or TIER-0 verdict into a brainstorm brief that
drops straight into a spec-driven build tool (e.g. GitHub spec-kit's
`/speckit.specify`) with no translation. One brief per workstream, one
folder per workstream.

## Brief rules

Use `assets/tier0-brainstorm-template.md`. Keep it product-and-problem
language: spec tools want the WHAT and WHY here; the tech stack belongs
in their planning step, so keep stack choices out except as constraints.

Every brief must contain:
1. **One-liner** and status line (EXTEND build vs TIER-0 test, caps,
   live-by date).
2. **Why now** — the verified facts, condensed, so the spec session
   doesn't re-litigate the research.
3. **Target user** — one concrete person, not a market.
4. **What to build (scope of THIS spec)** — numbered, concrete, and for
   Tier-0 briefs it describes a TEST SITE, not a product: lead magnet,
   card-verified pre-order, discovery/SEO pages, measurement. State
   explicitly that nothing behind the paywall gets built.
5. **Explicitly OUT of scope** — the things build-excitement will try to
   sneak in. For Tier-0: the actual product. For EXTEND: the later
   phases.
6. **Kill criteria and EV block** — copied verbatim from the contract so the metrics
   get built into the site from day one.
7. **Constraints & guardrails** — legal-marketing rules (e.g. never
   claim "makes you compliant" for compliance products; no implied
   official endorsement), tone rules, and sequencing rules (which
   workstream ships first; shared template opportunities between test
   sites to stay inside build caps).
8. **Open questions** — 3–5 genuine decisions, pre-written as fodder for
   the spec tool's clarify step.

## Gate-zero candidates

If Phase 3 attached a gate zero, the brief has two parts: Part A is the
desk-research checklist with its deadline and kill conditions (no spec
tool involved); Part B is the Tier-0 brief, marked "spec only after
Part A passes".

## Handoff package

Deliver: the briefs as files, folder-creation commands for the user's
environment, the execution order with dates, and the checkpoint calendar.
Recommend placing each candidate's dossier alongside its brief in the
folder — during deep build sessions weeks later, the dossier is the
"why does this exist and when do I kill it" memory that prevents scope
creep. Offer a portfolio calendar file when there are 2+ live contracts.
